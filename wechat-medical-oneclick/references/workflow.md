# 一键工作流

## 1. 建立目录与检索医学来源

1. 用 2～4 个简短英文单词或拼音建立独立文章目录，并创建 `imgs/prompts/` 与 `references/`。
2. 必须联网核对截至执行当日的资料。优先中国正式指南、中华医学会及国家级专业学会；必要时补充 WHO、ADA、EASD、ESC、AHA/ACC、KDIGO 等官方来源。
3. 技术和医学检索只引用指南发布机构、学会官网、期刊指南原文或正式共识等一手来源。记录资料名称、机构、年份、版本/更新日期和正式链接。
4. 对所有数字、单位、阈值、时间范围、频率、适用人群和限定词逐项建立来源映射。无法可靠核对的数字不写入正文或图片。

## 2. 写作与医学安全

围绕用户标题确定的要点写适合普通中国成年人、中老年患者及家属阅读的文章。要点数量必须来自证据，不得凑数。

正文必须写清：

- 适用人群；
- 不适用或需要特别谨慎的人群；
- 老年人低血糖风险；
- 个体化目标及其适用条件；
- 何时需要尽快就医；
- 哪些情况必须由医生调整治疗方案；
- 不自行加药、减药、换药或停药；
- 健康科普免责声明。

不得提供个体诊断或个体治疗方案。药物、妊娠、急症、严重肝肾功能异常、认知障碍、反复低血糖等内容要明确提示就医或由医生评估。

保存 `article-raw.md`，并在 `medical-review.md` 中单列：已核对内容、数字核对表、需要人工确认的医学内容、潜在误读点。

## 3. 格式化

调用 `$baoyu-format-markdown`，固定保留用户标题并自动选择“优化格式”。本次一键调用已授权跳过标题选择和格式确认。只调整标题层级、段落、列表、重点标记和中英文间距；不得改变、增删或改写医学结论。

保存 `article-analysis.md` 与 `article-formatted.md`。Frontmatter 至少包含 `title`、`slug`、`summary`、`description` 和 `coverImage: imgs/01-cover.png`。

## 4. 一次性规划并生成全部图片

调用 `$baoyu-article-illustrator`，设置为 mixed、rich（6～8 张）、warm hand-drawn、奶油/深棕/橙/浅绿、中文、竖版 2:3、Codex `imagegen`。本工作流明确表示“直接生成、不用确认”，因此跳过其确认门，不在封面后暂停。

配图数量包含封面。每张只表达一个中心结论。大纲逐张写明：编号、插入位置、中心结论、画面内容、必须出现的准确文字/数字/单位/限定词、不得出现的错误表达、文件名。

在任何出图前完成并核验本批次全部提示词文件。每个提示词必须包含 ZONES、LABELS、COLORS、STYLE、ASPECT，并写明：

- 参考 `references/female-clinician-reference.jpg`；
- 固定人物特征和统一色板；
- 只能使用已审核正文中的文字；
- 禁止二维码、Logo、水印、药品品牌、虚构数据和个体治疗方案；
- 标题逐字一致，不得漏字或改字；
- 竖版 2:3，适合手机阅读。

一次性提交全部图片，按后端能力分批并行，默认每批最多 4 张。不要使用子代理仅为了并行出图。

逐张检查中文、术语、数字、单位、时间、频率、适用人群和限定词。出现错字、乱码、错误数字或错误单位时，从修订后的新提示词重新生成；禁止程序涂改图片文字。将合格图片插入副本 `article-illustrated.md`，不得覆盖无图原稿。

## 5. 生成可带图复制的微信预览

运行 `scripts/build_wechat_preview.py`。它必须：

- 为二级章节添加连续 `PART 01`、`PART 02`……；
- 使用白底、深棕标题、摸鱼绿重点、浅绿分隔线和圆角图片卡；
- 把所有本地图片转为 `data:` URL，写入标准 `<img>` 标签；
- 不使用 CSS 背景图、`blob:`、`file://`、相对路径或临时网络图片；
- 给所有正文样式写内联 CSS，保证复制后尽可能保留；
- 提供“复制排版正文（含图片）”按钮；
- 图片未全部加载时禁用复制；
- 在页面显示预期图片数和已加载图片数。

复制按钮必须复制 `#output` 的富文本 HTML，而不是只复制 `innerText`。优先选择渲染后的 `#output` 并调用浏览器富文本复制；失败时再用 Clipboard API 写入 `text/html` 与 `text/plain` 两种格式。

## 6. 完成前核验

核对并报告：

- 文章摘要和核心要点；
- 需要人工确认的医学内容；
- 参考资料数量与概览；
- 图片数量及每张中心结论；
- 中文、数字、单位和限定词检查结果；
- 二级章节数与 PART 编号数；
- Markdown 图片数、HTML `<img>` 数和成功内嵌数三者相等；
- 外部链接数与免责声明数；
- 所有输出绝对路径。

如果图片数不一致或有图片无法解码，视为失败并修复，不得报告“可复制”。提醒用户：粘贴进微信公众号编辑器后，先目视确认图片数量再保存草稿；不得把“复制成功”误报为“微信已保存草稿”。
